# uv.lock — quick primer

> First-day notes for someone who's never used uv.lock. Personal voice, plain language.

## What is it?

uv.lock is a lockfile generated by `uv` — the fast Python package manager. If you know `package-lock.json` from npm or `Cargo.lock` from Rust, you already understand the concept: it pins every single dependency (and sub-dependency) to exact versions so that everyone installing the project gets the same environment. uv writes it in a cross-platform TOML format.

## What does it do?

When you run `uv sync` or `uv add`, uv resolves all your dependencies against PyPI (or other indexes), figures out compatible versions, and writes the final resolution into `uv.lock`. Later, anyone who runs `uv sync` on the same project gets byte-for-byte the same package set — no surprises, no "works on my machine."

## Why does it exist?

Before lockfiles in the Python world, you'd list dependencies in `requirements.txt` with version ranges like `requests>=2.28`. That means different people could install different versions depending on when they ran `pip install`. CI could pass on Monday and fail on Tuesday because a sub-dependency released a breaking change. Tools like `pip freeze` could snapshot your current environment, but that's manual and easy to forget.

uv.lock automates this. It's uv's answer to what Poetry's `poetry.lock` and PDM's `pdm.lock` do, but designed for uv's speed-focused resolver. It lives alongside `pyproject.toml` as the source of truth for what's actually installed.

## Key terminology

- **Lockfile** — A file that records exact versions for every dependency and transitive dependency. Example: `uv.lock` in your project root after running `uv sync`.
- **Resolution** — The process of finding a set of package versions that satisfy all version constraints. Example: `uv lock` resolves constraints from `pyproject.toml` and writes results to `uv.lock`.
- **`uv sync`** — The command that reads `uv.lock` and installs exactly those versions into the virtual environment. Example: `uv sync` after cloning a repo sets up the environment.
- **`uv add`** — Adds a package to `pyproject.toml` and updates `uv.lock` in one step. Example: `uv add requests` adds requests and its dependencies.
- **`uv lock`** — Re-resolves dependencies without installing anything. Example: run `uv lock` to update the lockfile after editing `pyproject.toml` by hand.
- **`[metadata]` section** — Top-level section in uv.lock storing the manifest hash and resolver options. Example: uv checks this hash to detect if `pyproject.toml` changed.
- **`[[package]]` section** — One entry per resolved package with name, version, source, and hashes. Example: `[[package]] name = "requests" version = "2.32.3"`.
- **Transitive dependency** — A dependency of a dependency. uv.lock includes these too. Example: `urllib3` is a transitive dependency of `requests`.
- **Hash** — A cryptographic digest of a package archive, used to verify integrity. Example: `sha256:abc123...` in the `[[package]]` entry.
- **Cross-platform** — uv.lock can store different versions or sources for different OS/arch combinations. Example: platform-specific wheels for Linux vs macOS in the same lockfile.

## A tiny example

```bash
# Start a new project
uv init my-app
cd my-app

# Add a dependency — this creates uv.lock automatically
uv add requests

# Look at what got locked
head -5 uv.lock
```

This creates a project, adds `requests` as a dependency, and generates `uv.lock` with the exact resolved version of `requests` and all its transitive deps. Running `uv sync` anywhere else with this file produces the exact same environment.
