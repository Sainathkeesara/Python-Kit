# uv.lock — quick primer

> First-day notes for someone who's never used uv.lock. Personal voice, plain language.

## What is it?

I just learned about uv.lock and it's a lockfile generated by `uv`, the fast Python package manager. If you know `package-lock.json` from npm, the idea is the same: it pins every dependency to exact versions so everyone gets the same environment. uv writes it in a cross-platform TOML format.

## What does it do?

When you run `uv sync` or `uv add`, uv resolves all your dependencies against PyPI, figures out compatible versions, and writes the final resolution into `uv.lock`. Later, `uv sync` gives you byte-for-byte the same package set — no surprises.

## Why does it exist?

Before lockfiles, you'd list dependencies in `requirements.txt` with version ranges. Different people could install different versions depending on when they ran `pip install`. uv.lock automates this — it's uv's answer to what Poetry's `poetry.lock` does, but built for uv's speed-focused resolver.

## Key terminology

- **Lockfile** — Records exact versions for every dependency and transitive dependency. Example: `uv.lock` after `uv sync`.
- **Resolution** — Finding package versions that satisfy all constraints. Example: `uv lock` resolves constraints from `pyproject.toml`.
- **`uv sync`** — Reads `uv.lock` and installs exactly those versions. Example: `uv sync` after cloning a repo.
- **`uv add`** — Adds a package to `pyproject.toml` and updates `uv.lock`. Example: `uv add requests`.
- **Transitive dependency** — A dependency of a dependency. uv.lock includes these too.

## A tiny example

```bash
uv init my-app
cd my-app
uv add requests
head -5 uv.lock
```

This creates a project, adds `requests`, and generates `uv.lock`.
