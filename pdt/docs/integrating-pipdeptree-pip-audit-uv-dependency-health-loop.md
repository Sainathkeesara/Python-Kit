# Integrating pipdeptree with pip-audit and uv for a continuous dependency-health loop

## Purpose

A continuous dependency-health loop catches three classes of problems before they reach production: dependency drift (installed versions diverging from the lockfile), structural conflicts (two packages requiring incompatible versions of the same transitive dependency), and known vulnerabilities (packages with published security advisories). No single tool covers all three. pipdeptree surfaces the structural issues, pip-audit queries vulnerability databases, and uv manages the environment and lockfile that both tools depend on.

## When to use

Run the full loop on every push and pull request in CI. Run the lightweight subset (pipdeptree conflict check + pip-audit scan) as a pre-commit hook so contributors catch issues before pushing. Run it locally after `uv sync` or `uv lock` to verify the resolved set is clean before committing the lockfile.

## Prerequisites

- A Python project with a `pyproject.toml` declaring dependencies
- uv installed and available on PATH
- pipdeptree installed in the project environment
- pip-audit installed in the project environment
- A lockfile (`uv.lock`) generated by `uv lock`

## Steps

### 1. Configure tool sections in `pyproject.toml`

Add `[tool.pipdeptree]` and `[tool.pip-audit]` sections so both tools pick up project-specific defaults without extra CLI flags. The pipdeptree section typically excludes virtual-environment and build-artefact directories so the tree only shows project-relevant packages. The pip-audit section typically ignores directories that contain only development dependencies and can skip dependency scanning when you only care about directly declared packages.

### 2. Export a lockfile with `uv`

Run `uv lock` to regenerate `uv.lock` from `pyproject.toml`. The lockfile pins every transitive dependency to an exact version, which gives pip-audit a stable target and lets pipdeptree compare the resolved set against what the project declares.

### 3. Run the structural check with pipdeptree

Use pipdeptree to detect conflicts and cycles:

- `pipdeptree --warn summary` prints a concise list of version conflicts.
- `pipdeptree --reverse <package>` shows which top-level packages depend on a given transitive dependency, useful for deciding whether to upgrade or remove a leaf package.
- `pipdeptree --json` outputs the full tree as JSON for programmatic parsing.

In CI, fail the job if the conflict summary is non-empty or if the JSON output contains circular-dependency markers.

### 4. Scan for vulnerabilities with pip-audit

Use pip-audit against the resolved lockfile:

- `pip-audit --fix` reports vulnerabilities and upgrades affected packages where possible.
- `pip-audit --dry-run` (or the equivalent non-mutating scan flag) reports without modifying the environment.
- `pip-audit --ignore-dir <dir>` skips directories that contain only dev dependencies.

In CI, fail the job on any vulnerability with a fixable version available. For vulnerabilities without a fix, record the advisory ID and add an exception.

### 5. Combine into a single health-check script

Write a short script that runs both tools in sequence and exits non-zero if either reports a problem. Use uv to run the script inside the project's managed environment so the exact dependency set from `uv.lock` is what gets audited.

A typical sequence:

1. `uv sync --frozen` to ensure the environment matches the lockfile.
2. `pipdeptree --warn summary` and check for conflict output.
3. `pip-audit` against the synced environment and check the exit code.

### 6. Wire into CI

Add a job step that installs uv, syncs the lockfile, installs pipdeptree and pip-audit, and runs the health-check script. Cache the uv installation and the `.venv` directory between runs to reduce pipeline time. On failure, print the conflict and vulnerability output so the log contains enough context to fix the issue without rerunning locally.

## Verify

- `uv lock` completes without conflict markers in the output.
- `pipdeptree --warn summary` produces no `** Conflict **` lines.
- `pip-audit` exits with code 0 and reports zero vulnerabilities.
- The health-check script exits 0 on a clean project and non-zero when you intentionally introduce a conflict or a vulnerable package version.

## Common errors

**Lockfile drift after manual edits.** If `pyproject.toml` is edited but `uv.lock` is not regenerated, the environment and the lockfile diverge. Always run `uv lock` before the health-check step, or use `uv sync --frozen` to enforce that the environment matches the lockfile exactly.

**Dev-dependency noise in pip-audit scans.** Development dependencies often include unreleased or pre-release packages that trigger false-positive vulnerability warnings. Configure pip-audit to skip dev-only directories or restrict the scan to the runtime dependency set.

**Cycle detection false positives in monorepos.** pipdeptree reports cycles when two packages in the same workspace depend on each other through local path dependencies. These are intentional in some monorepo layouts. Filter cycle output by package name or path before treating it as a failure.

**pip-audit slow on large lockfiles.** A full scan of a large `uv.lock` can take minutes. Use `pip-audit --only` with a specific vulnerability database or run the scan on a schedule rather than on every commit if the project has hundreds of transitive dependencies.
